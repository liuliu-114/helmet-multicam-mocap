结果说明：

1. 数据集的相机矩阵、二维 GT、三维 GT 和刚体位姿 GT 内部一致，GT 几何基线误差接近浮点数值误差。
2. 实际图像链路的位置结果达到数毫米量级，主要系统偏差位于世界 Z 轴，约 `+1.926 mm`。
3. 姿态误差约 `0.76°`，主要小角度偏差位于第三个旋转向量分量，约 `+0.675°`，未达到目标表格中的 `0.15°` 指标。
4. 本序列的相机到刚体距离为 4.00–6.34 m，超出目标表格 0.2–2.3 m 的工作范围，不能把本实验直接表述为“2 m 验收结果”。
5. 数据使用红色自发光球形 Marker，而目标产品为被动红外反光 Marker；数据没有模拟镜头畸变、传感器噪声、同步误差和物理遮挡，因此不能代替真实硬件检测报告。
6. Marker 没有视觉编码。本次检测本身不使用 GT，但检测完成后的 ID 分配使用了 GT 辅助 Hungarian 匹配，因此尚未验证完全自主的跨相机 Marker ID 关联。

## 6. 实验链路与边界

### 6.1 三层验证设计

本实验拆成三层，避免把标签内部自洽性误写成图像算法精度。

1. **GT 几何基线**：`GT pixel_uv → 四相机 DLT → Kabsch → GT 比较`。该层不运行图像检测，仅验证几何代码。
2. **实际 PNG 四相机链路**：`PNG → 红色 Marker 检测 → GT 辅助 ID → 四相机 DLT → Kabsch → GT 比较`。本文主要结果来自该层。
3. **项目原生双相机范围对照**：只保留 Camera_01/02 的实际检测点，执行双视图 DLT 和 Kabsch，用于估计项目现有双相机能力范围。它不等于原生 C++ 节点完整输出，因为原生检测器和标定参数不适配该数据集。

### 6.2 GT 的使用位置

红色 Marker 本身没有编码，检测输出只有无 ID 的二维质心。本次协议中：

- HSV 阈值、形态学和连通域检测完全基于 PNG，不读取 GT；
- 检测完成后，使用 Hungarian 一对一最小距离匹配，把检测点关联到 `marker_id`；
- 匹配门限为 8 px；
- GT 3D 和 GT 刚体位姿只用于最终误差计算；
- 因此本实验验证检测、像素中心、三角化和位姿估计，但没有验证无 GT 的自主跨相机身份关联。

## 7. 算法实现

### 7.1 二维检测

每张 PNG 使用以下固定参数：

1. BGR 转 HSV；
2. 低端红/橙色范围：`H=0–25, S=45–255, V=100–255`；
3. 高端红色范围：`H=165–179, S=45–255, V=100–255`；
4. 两个掩膜取并集；
5. 使用 `3×3` 核执行一次闭运算，连接被白色高光分开的红色区域；
6. 连通域面积保留 `2–500 px`；
7. 连通域质心作为检测像素中心。

二维中心误差定义为：

```text
e_2d = sqrt((u_est-u_gt)^2 + (v_est-v_gt)^2)  [pixel]
```

### 7.2 相机投影

直接读取 `camera.json` 中 OpenCV 坐标约定的世界到相机变换：

```text
P_i = K_i [R_i | t_i]
```

世界坐标单位为 cm，因此三角化输出也是 cm。未额外拟合投影矩阵，也没有使用 GT 点反求相机参数。

### 7.3 多视图三角化

对同一 Marker 至少需要两个相机观测。每个观测 `(u_i,v_i)` 为 DLT 方程增加两行：

```text
u_i P_i[2,:] - P_i[0,:]
v_i P_i[2,:] - P_i[1,:]
```

堆叠全部有效视角后执行 SVD，取最小奇异值对应的齐次向量并归一化，得到世界坐标 `X_est`。Marker 三维误差为：

```text
e_3d_mm = 10 * ||X_est_cm - X_gt_cm||_2
```

同时计算三角化点回投到所有参与相机后的重投影误差。

### 7.4 刚体位姿估计

当一帧至少有三个已知 ID、非共线的三维 Marker 时，使用 Kabsch/SVD 求解：

```text
P_world_est ≈ R_est P_local + t_est
```

不估计尺度；若 SVD 结果 `det(R)<0`，修正反射。位置 GT 取 `object_pose_frames.json` 中 `T_object_to_world[:3,3]`，姿态 GT 取同一矩阵的 `[:3,:3]`。

### 7.5 指标定义

位置误差向量和标量：

```text
d_t = t_est - t_gt
e_t = ||d_t||_2
```

位置准度用 `e_t` 的 Mean/RMSE/P95/Max 和系统偏差 `mean(d_t)` 表示。位置精度代理定义为运动序列误差去除均值后的三维 RMS：

```text
precision_t = sqrt(mean(||d_t - mean(d_t)||^2))
```

姿态使用 SO(3) 相对旋转：

```text
R_error = R_est R_gt^T
theta = acos(clamp((trace(R_error)-1)/2,-1,1))
```

`theta` 是两个三维姿态之间的最小旋转角，避免欧拉角顺序、周期跳变和万向节问题。姿态偏差和精度代理使用相对旋转的小角度旋转向量统计。

“精度代理”不是严格的重复性指标：本数据没有在同一静态位置重复测量，也没有 20°C、重复还原扫描等测试设计，因此只能表示这段运动轨迹上的去偏残差离散程度。

## 8. 项目原生 ROS 链路实跑

### 8.1 虚拟相机输入

服务器无真实摄像头。本次使用 `v4l2loopback` 创建 `/dev/video4` 和 `/dev/video7`，分别将 `Camera_01.mp4` 和 `Camera_02.mp4` 用 FFmpeg 循环推流，输出格式为 YUYV422。GStreamer 实际协商到：

```text
format=YUY2, interlace-mode=progressive
```

### 8.2 ROS 进程与话题

实际启动了项目 launch：

```bash
source /opt/ros/foxy/setup.bash
source install/setup.bash
ros2 launch mobile_mocap arducam_bringup.py
```

启动的六个进程为两组 `publish_feed`、两组 `find_markers`、一个 `triangulate` 和一个 `rigid_body_tracker.py`。ROS 图中出现以下话题：

```text
/camera0/feed
/camera0/pixel_markers
/camera1/feed
/camera1/pixel_markers
/camera1/debug_image
/triangulated_markers
/markersfused3d/debug
```

两次短运行中，GStreamer 预热占用约 30–35 s；延长到 90 s 后六个节点和话题均创建成功，但采样窗口内 `ros2 topic hz` 没有获得 feed/pixel marker 消息，`triangulated_markers` 也没有有效样本。因此没有把原生 ROS 话题输出用于精度统计。测试结束后已停止 FFmpeg 和 ROS 进程，没有遗留后台推流。

### 8.3 原生代码不适配原因

1. `find_markers.cpp` 面向近红外反光点：先去除绿色占优像素，再灰度阈值、Canny 和椭圆拟合；本数据是曝光较高场景中的红色自发光小球。
2. 项目原标定文件约为旧分辨率/旧相机参数，不是本数据的 1280×720 UE 相机矩阵。
3. `triangulate.cpp` 实际实现双相机；三相机分支标记为未实现，没有四相机融合实现。
4. `rigid_body_tracker.py` 默认配置为旧的三点 scalene 刚体，不是六点 `test_box_01`。
5. 原生二维跨相机关联使用图形描述子，源码中也注明应替换为极线匹配；它没有利用数据集提供的 Marker ID。

因此，报告中的有效精度来自针对该数据参数执行的离线项目方法链，而不是把不匹配的旧标定和 NIR 检测器输出强行解释为本数据结果。

### 11.3 位置精度代理

| 指标 | 数值 |

Z 方向系统偏差明显高于 X/Y，约占总偏差模长的主要部分。X 方向的随机离散最大。可能原因包括不同视角下球体可见轮廓不完整、红色质心与理论球心存在视角相关偏移，以及远距离下单像素角度误差被放大。

### 11.6 离线批处理耗时

正式评估运行的墙钟时间约 9.3 s，处理 90 组同步帧、共 360 张 PNG，并同时生成四类 JSON 和 12 张叠加图。按这次包含文件读写和报告产物生成的串行 Python 运行估算，吞吐约为 `9.7` 组四相机同步帧/s，或 `38.7` 张单相机图像/s，低于 30 组同步帧/s 的实时要求。

该耗时不是优化后的在线算法性能：脚本逐文件读取 PNG、逐帧构造大量 JSON、生成叠加图，且没有并行化、缓存或 GPU 加速。它只能说明当前离线评估程序不是实时实现，不能替代 ROS 节点端到端延迟和吞吐测试。

## 15. 误差来源分析

1. **像素量化与远距离放大**：4–6 m 距离下，约 1 px 的中心误差会造成数毫米三维误差。
2. **理论球心与可见红色质心不同**：Marker 被刚体遮挡或被高光切割时，连通域质心偏向可见区域。
3. **曝光偏高、Marker 较小**：数据说明也明确指出该数据不适合证明毫米级商业精度。
4. **无亚像素圆心模型**：当前采用连通域质心，没有球轮廓拟合、PSF 模型或亚像素优化。
5. **线性 DLT**：未执行以重投影误差为目标的非线性多视图优化，也未做 RANSAC 视角剔除。
6. **GT 辅助 ID**：错误 ID 关联风险被 GT 匹配显著降低，完全自主链路可能出现额外误差和失败帧。
7. **无物理遮挡标签**：无法严格区分漏检与实际不可见点，表观 Recall 不能作为检测器最终召回率。
8. **合成相机过于理想**：无畸变、噪声、运动模糊、曝光波动和同步偏差，真实硬件可能更差。
9. **样本短且单一**：只有 3 s、一个刚体和一条轨迹，不能覆盖工作空间、速度、姿态和 Marker 布局变化。

## 18. 最终结论与后续建议

本次实验已真实处理全部 360 张 PNG，并完成实际二维检测、GT 辅助身份关联、多视图三角化和刚体 6DoF 估计。四相机链路在 90 帧上实现 100% 位姿覆盖，位置 Mean/RMSE 为 `2.249/2.330 mm`，姿态 Mean/RMSE 为 `0.763/0.772°`。GT 基线接近零，证明误差主要来自图像中心检测和可见轮廓，而不是坐标转换错误。

当前数据足以证明四相机几何链路和姿态恢复代码能够工作，但不足以证明目标产品达到正式验收指标。下一阶段应：

1. 生成或采集 0.2–2.3 m 范围内、包含 1 m 和 2 m 固定测点的序列；
2. 在每个固定位置和姿态重复采样，用同一基准点还原计算真正的 RMS/RMSE 和重复性；
3. 提供物理遮挡真值，或只把实际可见 Marker 纳入 Recall 分母；
4. 使用与最终被动红外反光 Marker、镜头、曝光和同步条件一致的数据；
5. 实现无需 GT 的极线约束、多视图几何和刚体模型联合 ID 关联；
6. 增加亚像素圆心、非线性重投影优化、RANSAC 视角剔除和时序滤波，并分别报告有/无后处理结果；
7. 将四相机融合、六点刚体配置和正确相机参数接入 ROS 节点，再测实时频率、端到端延迟、接入时间和长时间稳定性。

在这些条件补齐之前，最严谨的表述是：**该合成功能验证集上，四相机实际图像链路达到约 2.25 mm 平均位置误差和 0.76° 平均姿态误差；位置达到数毫米量级，姿态尚未达到 0.15° 目标，且结果不构成 2 m 被动红外硬件验收结论。**
