# dataset_rigidbody_0001 算法使用说明

## 1. 数据集定位

本数据集由 Unreal Engine 5 仿真生成，用于验证以下算法链路：

```text
四相机同步图像/视频
-> 红色 Marker 二维检测
-> 跨相机 Marker 匹配
-> 多相机三角化
-> Marker 三维坐标
-> 刚体位置和姿态估计
-> 与 UE Ground Truth 对比
```

当前数据集属于“功能链路验证集”，适合验证程序接口、坐标转换、三角化和姿态估计是否正确。当前画面曝光偏高，Marker 在画面中较小，尚不建议直接用该数据集证明毫米级定位精度。

### 3.1 images/

定量算法的推荐输入。PNG 图像没有 MP4 的有损压缩，帧编号与 Ground Truth 直接对应。

### 3.2 videos/

MP4 用于：

- 快速观察运动是否连续；
- 快速接入现有视频检测程序；
- 演示检测、轨迹和姿态叠加结果；
- 测试算法的实时处理速度。

MP4 不建议作为最终精度评估输入，因为 H.264 压缩可能改变 Marker 边缘和中心像素。正式计算二维中心误差、三维位置误差时应使用 `images/` 中的 PNG。

### 3.3 camera.json

包含每台相机的：

- 内参矩阵 `K`；
- `fx, fy, cx, cy`；
- 图像尺寸和 FOV；
- UE 世界位置和旋转；
- `T_world_to_camera_opencv`；
- `T_camera_opencv_to_world`。

当前相机内参为：

```text
fx = 1108.5125168440816
fy = 1108.5125168440816
cx = 640.0
cy = 360.0
```

```text
K = [
  [1108.5125168440816, 0, 640.0],
  [0, 1108.5125168440816, 360.0],
  [0, 0, 1]
]
```

### 3.4 rigid_bodies.json

包含刚体尺寸、Blueprint 路径，以及六个 Marker 在刚体局部坐标系中的固定坐标。

姿态估计时应使用：

```text
rigid_bodies[0].markers[*].position_cm
```

作为模型点 `P_local`。

### 3.5 gt_2d_frames.json

二维 Ground Truth，核心路径为：

```text
frames[frame_index]
  .cameras[camera_id]
  .markers[*]
```

每个 Marker 包含：

- `marker_id`：Marker ID；
- `camera_xyz_cm`：OpenCV 相机坐标；
- `pixel_uv`：理论像素中心 `[u, v]`。

若 Marker 不在画面范围内，`pixel_uv` 为 `null`。

### 3.6 gt_3d_frames.json

每帧 Marker 三维 Ground Truth：

- `local_position_cm`：Marker 在刚体局部坐标系中的固定坐标；
- `world_position_cm`：Marker 在 UE 世界坐标系中的真实坐标。

### 3.7 object_pose_frames.json

每帧刚体真实位姿：

- `location_cm`：刚体原点世界坐标；
- `rotation_pitch_yaw_roll_deg`：UE 欧拉角表示；
- `quaternion_xyzw`：四元数；
- `T_object_to_world`：刚体局部坐标到世界坐标的 4 x 4 变换矩阵。

姿态验证的优先级建议为：

```text
T_object_to_world > quaternion_xyzw > rotation_pitch_yaw_roll_deg
```

不要直接对欧拉角逐项相减。欧拉角存在旋转顺序、周期跳变和万向节问题。

### 3.8 visibility.json

当前仅提供：

- `in_front`：Marker 是否在相机前方；
- `in_frame`：投影是否落在图像范围内；
- `occlusion_tested`：当前固定为 `false`。

因此 `in_frame = true` 不代表 Marker 一定没有被刚体遮挡。算法检测率统计时，需要结合实际图像判断可见性。

### 3.9 gt_2d.json 和 gt_3d.json

若目录中存在这两个文件，请将其视为兼容旧流程的单帧/遗留文件。v0.5.4 的权威逐帧真值是：

```text
gt_2d_frames.json
gt_3d_frames.json
```

## 4. 坐标系约定

### 4.1 UE 世界坐标

```text
+X：房间长度方向
+Y：房间宽度方向
+Z：向上
单位：cm
```

### 4.2 OpenCV 相机坐标

```text
+X：图像右方
+Y：图像下方
+Z：相机前方
单位：cm
```

`camera.json` 中矩阵按行存储，使用方式为：

```text
p_camera = T_world_to_camera_opencv @ p_world
```

齐次世界点：

```text
p_world = [Xw, Yw, Zw, 1]^T
```

取 `T_world_to_camera_opencv` 的前三行：

```text
[R | t] = T_world_to_camera_opencv[0:3, 0:4]
```

相机投影矩阵为：

```text
P = K @ [R | t]
```

## 5. 如何读取 MP4

四个 MP4 均为 30 FPS，帧序号从 0 开始。

```python
import cv2

cap = cv2.VideoCapture("videos/Camera_01.mp4")
frame_index = 0

while True:
    ok, frame = cap.read()
    if not ok:
        break

    # frame 对应 gt_2d_frames.json 中 frames[frame_index]
    # 在此执行红色 Marker 检测

    frame_index += 1

cap.release()
```

四路视频同步读取时，每次分别读取一帧，并使用相同的 `frame_index`：

```python
caps = {
    camera_id: cv2.VideoCapture(f"videos/{camera_id}.mp4")
    for camera_id in ["Camera_01", "Camera_02", "Camera_03", "Camera_04"]
}

for frame_index in range(90):
    frames = {}
    for camera_id, cap in caps.items():
        ok, frame = cap.read()
        if not ok:
            raise RuntimeError(f"{camera_id} 缺少第 {frame_index} 帧")
        frames[camera_id] = frame
```

定量评估时更推荐：

```python
frame = cv2.imread(f"images/{camera_id}/frame_{frame_index:04d}.png")
```

## 6. 二维 Marker 检测

当前 Marker 为红色弱自发光球体。基础方法可以采用 HSV 阈值、形态学处理和连通域中心提取。

```python
import cv2
import numpy as np

def detect_red_markers(frame_bgr):
    hsv = cv2.cvtColor(frame_bgr, cv2.COLOR_BGR2HSV)

    mask1 = cv2.inRange(hsv, (0, 80, 100), (12, 255, 255))
    mask2 = cv2.inRange(hsv, (168, 80, 100), (179, 255, 255))
    mask = cv2.bitwise_or(mask1, mask2)

    kernel = np.ones((3, 3), np.uint8)
    mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN, kernel)

    count, labels, stats, centers = cv2.connectedComponentsWithStats(mask)
    detections = []
    for index in range(1, count):
        area = stats[index, cv2.CC_STAT_AREA]
        if 2 <= area <= 500:
            detections.append(tuple(centers[index]))
    return detections, mask
```

阈值和面积范围仅作为起点，应根据实际图像调节。当前 Marker 较小，不建议使用过大的形态学核。

## 7. 如何验证二维识别正确性

### 7.1 GT 辅助匹配

检测结果只有二维点，红色 Marker 本身没有编码，不能仅按画面从左到右固定编号。

第一轮验证可以使用 GT 辅助匹配：

1. 读取该帧、该相机所有非空 `pixel_uv`；
2. 计算检测点和 GT 点之间的欧氏距离矩阵；
3. 使用 Hungarian 算法进行一对一最小代价匹配；
4. 距离超过阈值的匹配记为错误检测。

### 7.2 二维中心误差

对匹配成功的 Marker：

```text
e_2d = sqrt((u_est - u_gt)^2 + (v_est - v_gt)^2)
单位：pixel
```

建议统计：

- 检测率 Recall；
- 误检率；
- 平均中心误差；
- 中心误差 RMSE；
- P95 中心误差；
- 每台相机分别统计结果。

### 7.3 叠加检查

将检测中心和 GT 中心画在原图上：

```text
绿色十字：检测结果
蓝色圆圈：GT pixel_uv
红线：匹配关系
```

若坐标转换正确，GT 圆圈应覆盖在红色 Marker 中心附近。

## 8. 多相机三角化

### 8.1 组装投影矩阵

对每台相机：

```python
K = np.asarray(camera["intrinsics"]["K"], dtype=float)
T_w2c = np.asarray(
    camera["extrinsics"]["T_world_to_camera_opencv"],
    dtype=float,
)
P = K @ T_w2c[:3, :]
```

### 8.2 双相机三角化

已知同一个 Marker 在两台相机中的像素坐标：

```python
point_4d = cv2.triangulatePoints(
    P1,
    P2,
    np.asarray([[u1], [v1]], dtype=float),
    np.asarray([[u2], [v2]], dtype=float),
)
point_world = point_4d[:3, 0] / point_4d[3, 0]
```

输出世界坐标单位为 cm，因为外参平移单位为 cm。

### 8.3 四相机三角化

四相机建议采用多视图 DLT 或非线性重投影优化：

```text
最小化 sum_i ||project(P_i, X) - x_i||^2
```

并使用 RANSAC 或重投影误差剔除错误视角。

### 8.4 三维 Marker 误差

与 `gt_3d_frames.json` 中同 ID 的 `world_position_cm` 比较：

```text
e_3d_cm = ||X_est - X_gt||_2
e_3d_mm = 10 * e_3d_cm
```

建议统计每个 Marker 和整体的 Mean、RMSE、Std、P95、Max。

## 9. 刚体位置和角度估计

### 9.1 输入

对同一帧准备至少三个不共线的对应点：

```text
P_local：rigid_bodies.json 中的 Marker 局部坐标
P_world_est：多相机三角化得到的 Marker 世界坐标
```

本数据集六点为非对称、非共面布局，建议尽量使用四个及以上有效 Marker。

### 9.2 刚体变换估计

求解：

```text
P_world_est ~= R_est @ P_local + t_est
```

可以使用 Kabsch/SVD：

1. 分别计算局部点和世界点的质心；
2. 点集去中心化；
3. 计算协方差矩阵；
4. SVD 得到旋转矩阵；
5. 若 `det(R) < 0`，修正反射；
6. 计算 `t = centroid_world - R @ centroid_local`。

不要估计尺度，刚体尺度固定为 1。

### 9.3 位置验证

GT 位置读取：

```text
object_pose_frames.json
  -> frames[frame_index]
  -> pose.location_cm
```

位置误差：

```text
e_t_cm = ||t_est - t_gt||_2
e_t_mm = 10 * e_t_cm
```

位置偏差向量：

```text
bias = mean(t_est - t_gt)
```

位置准度主要观察 Bias 或 Mean Error，位置精度主要观察重复误差的 Std/RMSE。具体指标定义需要与项目验收口径保持一致。

### 9.4 角度验证

GT 旋转矩阵读取：

```text
R_gt = T_object_to_world[0:3, 0:3]
```

估计旋转矩阵为 `R_est`。相对旋转：

```text
R_error = R_est @ R_gt.T
```

角度误差：

```text
theta_rad = acos(clamp((trace(R_error) - 1) / 2, -1, 1))
theta_deg = theta_rad * 180 / pi
```

Python 示例：

```python
import numpy as np

def rotation_error_deg(R_est, R_gt):
    R_error = R_est @ R_gt.T
    cosine = (np.trace(R_error) - 1.0) / 2.0
    cosine = np.clip(cosine, -1.0, 1.0)
    return np.degrees(np.arccos(cosine))
```

该角度是两个三维姿态之间的最小旋转角，比逐项比较欧拉角更可靠。

## 10. 建议的完整算法顺序

### 阶段 A：使用 GT 验证几何代码

```text
读取 gt_2d_frames.json 的 pixel_uv
-> 直接多相机三角化
-> 与 gt_3d_frames.json 比较
-> 用三维点恢复刚体姿态
-> 与 object_pose_frames.json 比较
```

这一阶段不运行图像检测。理论上误差应接近数值计算误差。如果误差很大，优先检查相机矩阵、坐标轴和 Marker ID 对应关系。

### 阶段 B：验证二维检测

```text
PNG/MP4 检测红色中心
-> 与 gt_2d_frames.json 匹配
-> 统计像素误差、漏检和误检
```

### 阶段 C：端到端验证

```text
图像检测
-> 跨相机 Marker 匹配
-> 三角化
-> 刚体姿态估计
-> 位置/角度误差统计
```

这种分阶段方式可以判断问题发生在检测、跨相机匹配、三角化还是姿态估计。

## 12. 当前限制

1. 当前仅有一个盒状刚体，尚未加入头盔、武器和器材。
2. Marker 为红色球形点，不是最终贴片。
3. Marker 没有视觉编码，跨相机 ID 匹配需要算法或 GT 辅助。
4. 当前没有模拟镜头畸变、传感器噪声和相机同步偏差。
5. `visibility.json` 没有物理遮挡结果。
6. 当前场景曝光偏高，Marker 像素尺寸较小。
7. MP4 经过 H.264 压缩，精度评估应优先使用 PNG。
