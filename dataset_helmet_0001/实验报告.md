## 2. 结论摘要

使用与上一份刚体实验完全相同的正式参数（红色 HSV 检测、连通域面积 `2–500 px`、GT 辅助 Hungarian 匹配门限 8 px），四相机链路在全部 90 帧上恢复了头盔位姿。

| 指标 | 四相机实际 PNG 结果 |
|---|---:|
| 有效头盔位姿帧 | 90 / 90（100%） |
| 有效多视图 Marker 时刻 | 359 / 540（66.48%） |
| 每帧参与位姿 Marker | 89 帧为 4 点，1 帧为 3 点 |
| 二维匹配中心误差 Mean / RMSE | 1.770 / 2.246 px |
| Marker 三维误差 Mean / RMSE | 3.385 / 3.756 mm |
| 位置误差 Mean / RMSE | **3.100 / 3.155 mm** |
| 位置误差 P95 / Max | 4.152 / 4.704 mm |
| 位置系统偏差模长 | **2.911 mm** |
| 位置精度代理（去偏 3D RMS） | **1.215 mm** |
| 姿态测地误差 Mean / RMSE | **1.102 / 1.133°** |
| 姿态测地误差 P95 / Max | 1.639 / 1.846° |
| 姿态小角度偏差模长 | **0.994°** |
| 姿态精度代理（去偏 3D RMS） | **0.545°** |

核心结论如下：

1. 新数据的相机到头盔原点距离为 `1.245–1.934 m`，落在目标工作范围 `0.2–2.3 m` 内，比上一批 4–6 m 数据更接近 2 m 验收条件。
2. GT 的相机、二维投影、三维点和头盔位姿内部一致，GT 几何基线接近浮点数值误差。
3. 实际四相机位置误差约 3.10 mm，位置去偏离散约 1.22 mm；姿态误差约 1.10°，没有达到 `0.15°` 姿态目标。
4. 虽然数据定义了 H01–H06 六个 Marker，实际有效多视图位姿主要依赖 H01–H04。H05 在 8 px 门限下无匹配，H06 只有 17 个二维匹配且没有形成同帧双视图三角化。
5. `visibility.json` 只检查理论投影是否在画内，不检查头盔物理遮挡。大量红色可见区域的质心与理论 Marker 中心相差 10–30 px，因此 44.81% 的表观 Recall 不能解释为严格检测召回率。
6. 项目原生 ROS 双相机链路成功读取虚拟视频并将数据送至刚体跟踪器，但跟踪器因系统 SciPy 不支持 `Rotation.from_matrix` 而崩溃，没有原生 ROS 位姿输出。
7. 该数据仍为理想针孔 UE 合成数据，红色 Marker 不是最终被动红外反光 Marker，不能替代真实硬件检测报告。

## 9. 评估协议

### 9.1 三层结果

1. **GT 几何基线**：`GT pixel_uv → 四相机 DLT → Kabsch → GT`，只验证几何实现。
2. **正式实际图像链路**：`PNG → 红色检测 → GT 辅助 ID → 四相机 DLT → Kabsch → GT`，作为主结果。
3. **双相机范围对照**：仅使用 Camera_01/02 的实际检测点，测试项目当前双相机范围能否形成头盔位姿。

### 9.2 GT 使用边界

Marker 没有视觉编码。HSV 检测阶段不读取 GT；检测后使用 Hungarian 算法按像素距离进行一对一 ID 归属，门限 8 px。GT 3D 和头盔位姿只用于误差统计。

因此本实验验证真实图像中心、三角化和位姿拟合，但没有验证无 GT 的自主跨相机 ID 关联。完全自主链路的覆盖率和误差不会优于本文结果，且可能因错误对应进一步下降。

## 10. 算法与指标定义

### 10.1 二维检测

正式参数与上一数据集保持一致：

```text
HSV low red/orange: H 0–25, S 45–255, V 100–255
HSV high red:       H 165–179, S 45–255, V 100–255
Morphology:         3×3 close
Component area:     2–500 px
Detection centre:   connected-component centroid
GT match gate:      8 px
```

二维误差：

```text
e_2d = sqrt((u_est-u_gt)^2 + (v_est-v_gt)^2)
```

### 10.2 多视图三角化

直接读取 `camera.json` 的 `K` 和 `T_world_to_camera_opencv`：

```text
P_i = K_i T_world_to_camera_opencv[0:3,0:4]
```

对每个至少有两个相机观测的 Marker 堆叠 DLT 方程并执行 SVD。输出世界坐标单位为 cm，与 `gt_3d_frames.json` 比较后乘 10 得到 mm。

### 10.3 位姿估计

对至少三个非共线对应点，用 Kabsch/SVD 求解：

```text
P_world_est ≈ R_est P_local + t_est
```

不估计尺度，并修正 `det(R)<0` 的反射解。

### 10.4 准度与精度

位置误差向量和标量：

```text
d_t = t_est - t_gt
e_t = ||d_t||
```

位置准度报告 Mean、RMSE、P95、Max 和偏差 `mean(d_t)`。位置精度代理为运动序列去偏残差的三维 RMS：

```text
sqrt(mean(||d_t-mean(d_t)||^2))
```

姿态误差使用：

```text
R_error = R_est R_gt^T
theta = acos(clamp((trace(R_error)-1)/2,-1,1))
```

`theta` 是 SO(3) 测地角。姿态偏差和精度代理由小角度旋转向量计算，而不是直接相减欧拉角。

这里的“精度代理”不是 ISO 重复性：数据没有在同一静态位置、相同姿态下重复采样，也没有温度、重新安装、重复还原扫描设计。

## 11. 图像与 GT 对齐诊断

四路图像逐帧变化，GT 投影数学正确，但物理可见红色区域不总是覆盖理论中心。典型现象包括：

- Camera_01 第 0 帧可见大红色区域质心约为 `(901.9,440.2)` 和 `(867.8,505.8)`；六个理论中心中没有与第一个点相距 8 px 内的对应项。
- Camera_01 第 45 帧一处可见红色质心约为 `(564.6,307.3)`，相邻理论 Marker 中心可相差约 30 px。
- Camera_03/04 的若干正视 Marker 中心误差接近 1 px，说明图像和 GT 并非整体错帧或整体坐标错误。
- 四台相机无连续相同 BGR 帧；不存在统一时间偏移能够解释所有视角的偏差。

最合理的解释是：GT 给出 Marker 组件理论中心投影，而头盔几何会遮挡圆片；当只剩边缘、弧段或小片红色可见时，连通域质心与理论中心不同。由于 `occlusion_tested=false`，无法从 JSON 自动排除这些情况。

因此报告使用“匹配检测数”和“未匹配候选数”，不把全部未匹配候选武断地称为误检。

## 12. 项目原生 ROS 实跑

### 12.1 输入与启动

服务器无真实摄像头。使用 `v4l2loopback` 创建 `/dev/video4`、`/dev/video7`，将头盔 `Camera_01.mp4`、`Camera_02.mp4` 通过 FFmpeg 循环推送为 YUYV422。GStreamer 实际协商为：

```text
1280×720, 30/1 FPS, YUY2, progressive
```

运行：

```bash
source /opt/ros/foxy/setup.bash
source install/setup.bash
ros2 launch mobile_mocap arducam_bringup.py
```

两组 `publish_feed`、两组 `find_markers`、`triangulate` 和 `rigid_body_tracker.py` 均启动。刚体跟踪器收到三角化消息后进入 `markers_callback`，证明视频输入、检测/三角化链路实际产生了下游数据。

### 12.2 原生崩溃

原生刚体跟踪器随后崩溃：

```text
rigid_body_tracker.py, publish_pose
rot = R.from_matrix(rot)
AttributeError: type object 'Rotation' has no attribute 'from_matrix'
```

原因是系统 SciPy 1.3.3 只提供 `Rotation.from_dcm`。因此本次原生 ROS 链路没有可用于 GT 对比的位姿输出。

### 12.3 其他不适配项

即使修复 SciPy 接口，原生 ROS 结果仍不能直接作为本数据精度：

1. `find_markers.cpp` 面向近红外反光点，不是红色 UE 圆片检测器；
2. 原生标定文件不是本数据的 1280×720、70° FOV 相机参数；
3. `triangulate.cpp` 只实现双相机，三相机分支未完成，没有四相机融合；
4. `rigid_body_tracker.py` 默认是旧三点 scalene 刚体，不是六点头盔；
5. 原生跨相机几何对应没有使用头盔 Marker ID。

测试结束后已停止 ROS 和 FFmpeg，没有遗留后台进程。

位置误差以系统偏差为主。Mean 相对 2 m 的数值比例为 `0.155%`，远小于 4%，但数据没有严格 2.000 m 固定测点，且为理想合成相机，不能写成正式硬件 `@2m` 通过结论。

### 15.3 位置精度代理

| 指标 | 数值 |

## 20. 误差来源与限制

1. `in_frame` 没有物理遮挡语义，表观 Recall 分母不准确；
2. 圆片只露出边缘时，连通域质心不是组件理论中心；
3. H05/H06 没有形成有效多视图，位姿几何退化为 H01–H04；
4. H04 的三维 Mean 达 5.772 mm，显著高于其他有效 Marker；
5. 当前是整数/浮点连通域质心，没有轮廓模型或亚像素拟合；
6. DLT 是线性解，没有非线性重投影优化或 RANSAC 视角剔除；
7. GT 辅助 ID 消除了大部分错误对应风险，完全自主结果可能更差；
8. 理想针孔模型无畸变、噪声、运动模糊、滚动快门和同步偏差；
9. 仅 3 s、一个头盔和一条轨迹，没有重复静态测点；
10. 红色 UE Marker 不是被动红外反光材料；
11. 离线 Python 实现不是实时系统；
12. 原生 ROS 节点存在 SciPy 兼容崩溃、旧标定、双相机和旧刚体配置问题。

## 23. 最终结论与建议

本次已完整解压和审计头盔数据，实际处理全部 360 张 PNG，并执行二维红点检测、GT 辅助 ID、多视图三角化和头盔位姿恢复。四相机在 1.245–1.934 m 范围内恢复 90/90 帧，位置 Mean/RMSE 为 `3.100/3.155 mm`，姿态 Mean/RMSE 为 `1.102/1.133°`。位置达到数毫米量级，姿态明显未达到 0.15°。

结果的最大问题不是相机距离，而是有效 Marker 几何：H05/H06 没有进入多视图融合，H04 又存在较大的三维误差，最终几乎所有位姿都由 H01–H04 四点估计。下一阶段优先级应为：

1. 增加物理遮挡射线标签，明确每个 Marker 是否真实可见；
2. 检查 H05/H06 的 Blueprint 组件原点、视觉子组件变换和导出局部坐标是否一致；
3. 调整头盔 Marker 朝向和布局，使至少四台相机中的两台能同时看到每个 Marker；
4. 使用椭圆/圆片透视模型和亚像素中心，而不是部分可见区域质心；
5. 实现多视图极线与刚体几何联合 ID，不依赖 GT；
6. 加入非线性重投影优化、鲁棒损失和坏视角剔除；
7. 修复原生 ROS 的 SciPy 兼容接口，导入本数据相机矩阵和六点头盔配置，实现真正四相机融合；
8. 在 1 m、2 m 固定位置进行重复静态采样，按统一 RMS/RMSE 口径重新验收；
9. 使用真实被动红外 Marker、真实相机畸变、曝光和同步条件复测。

当前最严谨的结论是：**该 UE 合成头盔数据上，四相机实际图像链路实现 100% 帧级位姿覆盖，位置平均误差约 3.10 mm、姿态平均误差约 1.10°；位置为数毫米量级，姿态未达到 0.15°，且六个 Marker 中只有 H01–H04 形成稳定多视图结果。**
